What is PromptFlow™

Write a program. Connect neural networks. Run it.

PromptFlow™ is a programming language for prompting neural networks. A PromptFlow™ process is an executable program that describes a sequence of model invocations — its inputs, its parameters, the chain of steps that feed one model’s output into the next, and the shape of the result.

Processes are stored as .promptflow files: electronic data files featuring programming data in the field of AI. A .promptflow download is an executable ZIP archive. It preserves a workflow’s step graph, prompts, and packaged dependencies. Model outputs, live search results, and provider availability can change between runs.

The PromptFlow™ online software lets you author, execute, retrieve and compose programs in your browser. Prompts and programming data remain available in the online editor. The PromptFlow™ downloadable CLI and interpreter runs saved programs on your own machine. Both use the same structured step graph and editable prompts.

The .promptflow file

One download. A structured, runnable bundle.

You can run the archive directly, or extract it to inspect and edit its files. The structure grows with the workflow: a text process may need only a prompt; a composed process can include other processes and custom tools.

Start with these three files.

README.md
The process overview and instructions for running its download.
manifest.json
The executable step graph: inputs, outputs, tool parameters, prompt references, and dependency mappings. This is what the runner follows.
spirit.md
The goal and original design intent, plus a prompt for rebuilding the process with newer models or tools.

This is an example tree. prompts/ contains the prompt files the workflow uses. resources/ holds editable starter material, such as working website or game source. Optional folders and metadata appear only when needed or provided.

Independent steps can share a parallel_group. The interpreter runs up to three at a time and waits for their results before dependent steps begin. A group cannot read another member’s unfinished output. Version 0.4.0 also supports self-contained website/game exports and ZIP packs of Markdown, CSV and JSON files.

What the other files do
__main__.py & process.py
Entry points that start the included runner. Python can execute the archive without extracting it first.
_promptflow_runtime.py
The bundled execution engine. It resolves inputs, runs steps, reports activity, and saves results.
prompts/*.txt
Editable text prompts. Names connect each file to a step and field; for example, summarize__user.txt is the user prompt for the summarize step. Loop prompts include their parent step in the filename.
requirements.txt
Python dependencies used by the workflow and its nested processes. It can be empty. Text and built-in search steps do not require fal; fal media steps do.
recipes/
Custom Python tools packaged with the process. Built-in tools are handled by the runtime and do not each need a file here.
processes/
Included child workflows, each with its own manifest, prompts, and runtime files. The parent manifest maps process IDs to these folders. A child must be accessible when the bundle is exported.
utility.md, discoverability.md & stats.md
Optional usage guidance, discovery metadata, and a snapshot of recorded statistics. These describe the process; they do not define its execution.
original.py
A reference copy of the original Python listing. Change the manifest and prompt files to change the exported workflow.

prompts/summarize__user.txt
Summarize the following text into three concise bullets:
{{user_text}}

{{user_text}} resolves to the supplied input. A later step can use {{summarize.text}} for this step’s result. JSON-producing steps expose parsed values such as {{classify.parsed.items}}, which a loop can consume.

From download to first run

Use Python directly, or install the CLI.

Download a process from its Download .promptflow action. New bundles include their runtime and require Python 3.9+. Set the provider keys the process uses, then check its setup before running.

Run a downloaded bundle
No CLI install required
python "my-process.promptflow" --text "your input" --check
python "my-process.promptflow" --text "your input"

--check checks inputs, required keys, and local dependencies without provider calls. It cannot confirm whether a key is valid, a model is available, or the generated result will be correct. On macOS/Linux, use python3 if that is your Python command.

Install the CLI from the download

Download the CLI ZIP, extract it, and open a terminal inside the extracted promptflow-cli folder that contains pyproject.toml. There is currently no promptflow-interpreter package on PyPI. The commands below install the downloaded source folder.

Windows · PowerShell 
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\promptflow.exe --help
.\.venv\Scripts\promptflow.exe run "my-process.promptflow" --text "your input" --check
.\.venv\Scripts\promptflow.exe run "my-process.promptflow" --text "your input"
macOS / Linux 
python3 -m venv .venv
.venv/bin/python -m pip install .
.venv/bin/promptflow --help
.venv/bin/promptflow run "my-process.promptflow" --text "your input" --check
.venv/bin/promptflow run "my-process.promptflow" --text "your input"

Put the process download in the working folder or replace its filename with the full path. These commands work without activating the virtual environment. For the shorter promptflow commands below, activate it first or keep using the full executable path above. Installation needs internet access for the CLI’s Python dependencies.

For example, set $env:ANTHROPIC_API_KEY = "your-key" in PowerShell or export ANTHROPIC_API_KEY="your-key" in bash. Credentials are supplied separately; keep key values out of shared bundles.

Local and hosted runs have different billing. A local file run uses your provider accounts directly and does not require PromptFlow login or spend PromptFlow credits. A hosted run by process ID uses your PromptFlow account, shows a quote, and uses platform billing, including applicable creator fees.

Progress and elapsed-time updates appear in the terminal. JSON results go to standard output and a new file in promptflow-output/; use --output-dir to choose another folder. A local run can still need internet access for model and search calls.

Tell the interpreter what to prepare

Separate your instructions from your input data.

Use --text for data the workflow should process. Use --instructions when the interpreter should first generate, research, or transform inputs for that workflow. Give the run a recognizable name with --name.

A named run with synthetic inputs
Installed CLI
promptflow run "my-process.promptflow" --name "Sample data test" --instructions "Generate five clearly labeled synthetic input records, then run the workflow" --max-output-tokens 2048

The local interpreter makes a planning call, saves a preparation-plan JSON file, and asks for confirmation before generating the inputs and running the workflow. The planning call can incur provider cost even if you cancel. For scripts, --yes accepts the preparation plan.

Preparation can use AI text, Brave search, OpenAI image generation, and media tools already available in the bundle, with the necessary keys. It is limited to 12 preparation steps. Missing capabilities or essential details produce an error rather than a silently incomplete run.

The saved workflow stays unchanged. --check makes no planning call and cannot validate data that has not been generated yet. Use --model and --max-output-tokens to control local text-model usage; these are not a total spending cap for search, images, media or repeated steps.

In the web interpreter, select a process and describe what to prepare. Review the run’s inputs, models and quote before starting it. Use Model & API access to choose models and output limits. Hosted runs can also use --max-run-tokens in the CLI; that compute-credit limit does not apply to a local bundle.

Make it yours

Edit the prompts. Keep the connections intact.

Extract the archive to edit prompt wording or the manifest’s step graph. Preserve references such as {{previous_step.text}} and update their IDs when you rename steps. Nested processes have their own prompts and manifests inside processes/.

Extract, inspect and run
Use your virtual environment’s Python
python -m zipfile -e "my-process.promptflow" ./my-process
# Review requirements.txt and any custom recipes before installing.
python -m pip install -r ./my-process/requirements.txt
python ./my-process/process.py --text "your input" --check
python ./my-process/process.py --text "your input"

You can also run the extracted folder with promptflow run ./my-process --text "your input". Built-in text and search steps use the included runtime; custom Python recipes and fal media can require additional packages.

A download is a snapshot. Editing local files does not update the hosted process, and later web edits or model settings do not rewrite your download. Download again to pick up changes, including a newer bundled runtime. Editing original.py alone does not change the manifest-driven execution.

To share an edited archive, put __main__.py and manifest.json at the ZIP root and use the .promptflow extension. Include the referenced prompts, custom recipes and child processes. Leave out local credentials, virtual environments and generated outputs.

If a downloaded process will not run
Missing input or unresolved reference
Use the manifest’s declared inputs and check prompt references. Supply text with --text or a file with --input text=@input.txt. Use instructions to generate missing data.
Missing key or dependency
Read the preflight message, set the relevant environment variable, and install the reviewed requirements in the same Python environment used to run the process.
Older or incomplete export
Download the process again. The current web format is promptflow/1 JSON inside a ZIP; a YAML example or a file without an executable steps graph is not a replacement.
Provider failure
Check the reported step and provider access before retrying. Stopping the runner does not undo a request already submitted to a provider; that request may still be billed.
The three pools

Every process is system, private, or public.

System processes handle internal operations. Private processes hold your saved work. Public processes are workflows their authors have chosen to share, including your own published work. The planner considers processes you can access, subject to your scope and selection settings.

System

Internal operations

System processes provide internal operations for retrieval, generation and adaptation. User-published workflows appear separately in Public processes.

adaptation · optimization · consolidation · validation · evaluation · composition · retrieval · search
Private

Your saved work

Processes you create or copy remain private until you publish them. You control their prompts, steps and sharing settings.

drafts · forks · in-progress work · monetized processes · team-internal recipes
Public

Published by users

Browse workflows their authors have published. Run a relevant process, copy it to adapt its prompts, or use it as a step in a larger program. Publishing a process shares its definition; your run inputs and outputs remain private.

published processes · forks · composed pipelines · community-authored recipes
Retrieval

The planner finds processes you can access.

When a user describes what they want in natural language, the planner searches available system processes, published processes, and your own processes and either selects an existing process or composes a new one from the parts it finds. Retrieval is how PromptFlow™ resolves intent into a program.

Your private processes stay private. The planner can consider your own saved processes when your settings allow it. Other users’ private processes are not available to you. Drafts are excluded from general selection; open a draft explicitly when you want to review or test it.

Select a process directly to use that specific workflow. Scope and process-selection settings let you narrow which candidates the planner considers for other requests.

Execution and reuse

How PromptFlow™ programs run

A PromptFlow™ program defines inputs, prompts, model calls and outputs. The interpreter resolves references between steps and runs the program with the supplied data.

processes = programs
A .promptflow file is an executable description of work to be done by one or more neural networks. It records the inputs, parameters, step order and output format.
retrieval = process lookup
A natural-language request can select an available process from system, public and your own private work, within the selected scope. You can also select a process explicitly.
System processes
Internal operations such as search, generation and adaptation are listed in System. They are separate from workflows that users choose to publish.
composition = linking
One process invokes another by name. The result is a graph of authors’ work, linked through a single shared namespace. Public processes can call public processes; private processes can call public ones; system primitives underlie all of it.
forking = copy-on-write
When a user refines a system or public process, the system creates a private fork. The original is preserved. The fork can diverge freely. Both records remain in the graph, related by lineage.
Editable prompts and models
Prompts, model choices and step parameters are part of the program. Edit them, test the resulting output, and keep a version that works for your task.
