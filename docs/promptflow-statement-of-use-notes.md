## Before using evidence in a filing

1. Deploy the actual product page, CLI ZIP and example file, then verify the public URLs work. A local QA page or screenshot marked synthetic is not evidence of actual use in commerce.
2. Capture the deployed page with the mark, software description and working download link for the downloadable goods. Capture the live online offering and, where useful, its real editor/run interface for the services. Select evidence that supports the actual goods/services claimed in each class.
3. Preserve the exact URL and actual access/print date with each capture or in the filing's designated fields. The page's “Updated” date is not an access date. Do not backdate captures, alter screenshots to imply an earlier launch, or use generated covers as proof of actual software operation.
4. Verify genuine use in commerce and truthful first-use dates for every item claimed. A page revision or a download button alone does not establish all legal prerequisites. Have the filing reviewed against the application and prosecution history before signing.

These changes are intended to make the product's source and function clear; they do not guarantee USPTO acceptance or trademark clearance. No statement of use, declaration, filing fee or legal submission has been made.

## Primary guidance

- [USPTO specimen requirements](https://www.uspto.gov/trademarks/laws/specimen-refusal-and-how-overcome-refusal): actual use, association with identified goods/services, downloadable-software links, and URL/access-date requirements.
- [TMEP 904.03](https://tmep.uspto.gov/RDMS/TMEP/print?href=TMEP-900d1e636.html&version=current): software displays and electronic point-of-sale specimens.
- [USPTO trademark symbols](https://www.uspto.gov/trademarks/basics/what-trademark): ™ can indicate a claim before registration; ® is reserved for a registered mark within its registration's scope.
